## 발견된 보안 이슈

### 1. XSS (Cross-Site Scripting) 취약점

- **위험도**: 높음
- **위치**: `app/page.tsx:51`
- **상세**: `dangerouslySetInnerHTML`을 사용하여 사용자 입력을 HTML로 직접 렌더링

```tsx
<div
  className="preview-content max-w-none"
  dangerouslySetInnerHTML={{ __html: renderMarkdown(content) }}
/>
```

**문제점**:
- `renderMarkdown` 함수가 사용자 입력을 적절히 살균(sanitize)하지 않음
- 사용자가 악성 HTML/JS 코드를 입력할 수 있음
- 예시: `<script>alert('XSS')</script>`, `<img onerror="steal-cookie()">`

**권장 해결책**:
- `rehype-sanitize` 또는 `DOMPurify` 라이브러리 사용
- 기존 설치된 `remark` + `rehype` 체인 활용

---

### 2. 미사용 보안 라이브러리

- **위험도**: 중간
- **위치**: `package.json`
- **상세**: 마크다운 파싱 라이브러리가 설치되어 있으나 사용되지 않음

```json
"rehype-raw": "^7.0.0",
"remark": "^15.0.1",
"remark-html": "^16.0.1",
```

**문제점**:
- 커스텀 정규 표현식 파서 사용으로 보안 취약점 발생 가능
- 기존 라이브러리의 보안 패치 미적용

**권장 해결책**:
- `remark` + `rehype` 파이프라인으로 마크다운 처리 전환
- `rehype-sanitize` 추가 설치하여 HTML 살균 처리

---

### 3. 클라이언트 측 파일 검증

- **위험도**: 낮음
- **위치**: `app/page.tsx:179-185`
- **상세**: 파일 타입 검증이 `accept` 속성에만 의존

```tsx
<input
  ref={fileInputRef}
  type="file"
  accept=".md,.txt,.markdown"
  className="hidden"
  onChange={handleFileChange}
/>
```

**문제점**:
- 브라우저 개발자 도구로 `accept` 속성 우회 가능
- 악성 파일 업로드 가능성

**권장 해결책**:
- 파일 내용 기반 타입 검증 (magic number 확인)
- 파일 크기 제한 추가

## 결론

현재 코드는 **XSS 공격에 취약**한 상태. 마크다운 뷰어의 특성상 사용자 입력을 HTML로 렌더링해야 하므로, 적절한 HTML 살균(sanitization) 처리가 반드시 필요함.

기존에 설치된 `remark` 및 `rehype` 라이브러리를 활용하면 비교적 쉽게 보안을 강화할 수 있음.
