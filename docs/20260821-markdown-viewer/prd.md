# 제품 요구 사항 정의서 (PRD)

## 1. 개요

### 1.1 목적
이 PRD는 마크다운 뷰어 애플리케이션의 개발 요구사항을 정의합니다. 이 애플리케이션은 사용자가 마크다운 파일을 쉽게 탐색하고 조회할 수 있는 편리한 인터페이스를 제공하며, 마크다운 콘텐츠의 편집과 미리보기를 지원합니다.

### 1.2 범위
마크다운 뷰어 애플리케이션은 다음과 같은 기능을 지원할 것입니다:
- 사용 가능한 마크다운 파일 목록 표시
- 마크다운 콘텐츠 편집
- 렌더링된 마크다운 내용 미리보기
- 핵심 네비게이션 및 작업 항목

## 2. 사용자 요구사항

### 2.1 기능 요구사항

#### 2.1.1 네비게이션
- 애플리케이션은 인터페이스 상단에 네비게이션 바를 제공해야 합니다
  - 왼쪽 영역: 로고 표시
  - 오른쪽 영역: 작업 아이콘 (열기, 새로고침, 저장)

#### 2.1.2 콘텐츠 표시
- 메인 콘텐츠 영역은 두 개의 영역으로 분할되어야 합니다:
  - 왼쪽 영역: 편집 모드 (마크다운 소스 에디터)
  - 오른쪽 영역: 뷰어 모드 (렌더링된 마크다운 미리보기)
- 뷰어 영역에는 전체 화면 보기 토글 아이콘이 포함되어야 합니다

### 2.2 비기능 요구사항

#### 2.2.1 성능
- 애플리케이션은 사용자가 타이핑할 때 마크다운 콘텐츠를 실시간으로 렌더링해야 합니다
- 마크다운 파일 로딩은 반응성 있고 효율적이어야 합니다

#### 2.2.2 사용성
- 인터페이스는 직관적이고 사용자 친화적이어야 합니다
- 일반적인 작업 항목은 네비게이션 바를 통해 쉽게 접근할 수 있어야 합니다

#### 2.2.3 호환성
- 애플리케이션은 현대 웹 브라우저를 지원해야 합니다
- 애플리케이션은 다양한 화면 크기에서 반응형이고 접근 가능해야 합니다

## 3. 기술 요구사항

### 3.1 아키텍처
- 애플리케이션은 Next.js(앱 라우터)로 개발되어야 합니다
- 애플리케이션은 Tailwind CSS를 사용하여 스타일링되어야 합니다
- 마크다운 파싱은 remark와 rehype 라이브러리를 사용해야 합니다

### 3.2 파일 구조
- 모든 프로젝트 파일은 Next.js 프로젝트 규칙을 따르어야 합니다
- 마크다운 파일은 `/Users/dante/dev-workspace/md-viewer/docs`에 저장되어야 합니다
- 문서를 위한 새로운 폴더는 `YYYYMMDD-작업명` 형식으로 이름이 지정되어야 합니다(영어로)
- 각 문서 폴더에는 해당 작업과 관련된 문서 파일들이 포함되어야 합니다

### 3.3 구성 요소
- 네비게이션 바 컴포넌트: 페이지 상단에 고정
- 메인 콘텐츠 컨테이너: 스플릿 팬 레이아웃
  - 왼쪽 패널: 마크다운을 위한 코드 에디터
  - 오른쪽 패널: HTML 렌더러를 위한 미리보기
- 파일 작업을 위한 툴바 아이콘

## 4. 사용자 인터페이스 요구사항

### 4.1 네비게이션 바
- 페이지 상단에 고정
- 왼쪽 영역: 로고(텍스트 또는 이미지)
- 오른쪽 영역: 툴팁이 있는 아이콘
  - 열기: "파일 열기"를 나타내는 아이콘과 툴팁
  - 새로고침: "콘텐츠 새로고침"을 나타내는 아이콘과 툴팁
  - 저장: "변경 사항 저장"을 나타내는 아이콘과 툴팁

### 4.2 콘텐츠 영역
- 왼쪽과 오른쪽 패널 사이의 수평 분할
- 왼쪽 패널: 마크다운 지원 코드 에디터
- 오른쪽 패널: 렌더링된 문서 보기 영역
- 패널 사이의 재조정 가능한 구분선
- 뷰어 패널 우측 상단에 전체 화면 토글 아이콘

## 5. 비즈니스 규칙
- 마크다운 콘텐츠는 저장 전에 유효성 검사가 필요합니다
- 자동 저장 기능은 선택 사항이며, 사용자 환경에 따라 구현됩니다
- 사용자 데이터와 파일 선택 내용은 클라이언트 사이드에서만 관리되어야 합니다

## 6. 가정사항
- 사용자는 마크다운 문법에 익숙합니다
- 사용자는 웹 브라우저를 통해 애플리케이션에 접근합니다
- 애플리케이션은 Next.js 애플리케이션을 지원하는 서버에서 호스팅됩니다

## 7. 제약사항
- 마크다운 처리를 위한 외부 API 호출은 없습니다
- 모든 마크다운 파일은 `/docs` 디렉터리에 로컬로 저장되어야 합니다
- 인증 또는 권한 메커니즘은 필요하지 않습니다

## 8. 범위 밖 사항
- 사용자 계정 또는 인증
- 동시 편집 기능(협업)
- 다른 형식으로 내보내기 (PDF, DOCX 등)
- 표준 문법을 벗어난 고급 마크다운 확장

## 9. 성공 지표
- 애플리케이션은 마크다운 파일을 2초 이내에 로드하고 렌더링해야 합니다
- 애플리케이션은 일반적인 사용 중에 크래시가 발생해서는 안 됩니다
- 사용자 피드백은 인터페이스의 사용성과 만족도를 반영해야 합니다
